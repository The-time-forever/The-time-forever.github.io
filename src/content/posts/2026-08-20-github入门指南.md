## 一、注册一个 GitHub 账号

### 1.1 准备工作

在开始之前，请准备好以下信息：

| 项目 | 说明 |
| --- | --- |
| 邮箱 | 推荐使用常用邮箱（Gmail / QQ / 163 / Outlook 等），后续验证、通知都靠它 |
| 用户名 | 全网唯一，后续不能轻易修改，建议认真取名 |
| 密码 | 至少 8 位，建议包含大小写字母 + 数字 + 符号 |
| 手机号 | 部分地区注册时需要短信验证 |

> **小贴士**：用户名会出现在你的个人主页 `https://github.com/<username>` 中，也会出现在你贡献的每个仓库 URL 中，建议使用英文 + 数字的组合，避免中文或特殊字符。

### 1.2 注册流程

1. 打开 GitHub 官网：[https://github.com](https://github.com)
2. 点击右上角的 **Sign up**（注册）按钮
3. 填写邮箱，点击 **Continue**
4. 设置密码，点击 **Continue**
5. 设置用户名（Username），点击 **Continue**
6. 完成人机验证（拼图或字母验证）
7. 前往邮箱查收 GitHub 发送的验证邮件，点击邮件中的链接完成验证
8. （可选）绑定手机号、选择个人兴趣标签（这些都可以跳过）

注册完成后，你就拥有了一个属于自己的 GitHub 账号。

### 1.3 完善个人资料（建议）

进入 **Settings → Profile**，建议设置：

- **Avatar**：上传一张头像
- **Bio**：一句话介绍你自己
- **URL**：你的个人网站或博客
- **Pronouns**：代称（可选）

一个完善的个人资料会让协作者对你有更好的第一印象。

## 二、创建一个新仓库（Repository）

仓库（Repository，简称 Repo）是存放代码、文档、资源的地方，几乎所有操作都围绕仓库展开。

### 2.1 创建仓库的步骤

1. 登录 GitHub 后，点击右上角的 **+** 号 → **New repository**
2. 填写仓库基本信息：

| 字段 | 含义 | 示例 |
| --- | --- | --- |
| Repository name | 仓库名 | `my-first-repo` |
| Description | 仓库描述（可选） | "我的第一个 GitHub 仓库" |
| Public / Private | 公开 / 私密 | 详见下文 |
| Add a README file | 是否生成 README | 建议勾选 |
| Add .gitignore | 是否生成忽略文件 | 按语言选（如 Python、Node） |
| Choose a license | 是否添加开源协议 | 公开项目建议选（如 MIT） |

3. 点击 **Create repository**，仓库就创建成功了！

### 2.2 仓库地址说明

仓库创建后，会得到一个 URL，格式为：

```
https://github.com/<你的用户名>/<仓库名>.git
```

这就是后续 `git clone` 使用的地址。

## 三、设置仓库的公开（Public）与私密（Private）

GitHub 允许你随时切换仓库的可见性，这一节重点讲如何设置。

### 3.1 Public（公开）仓库

- **任何人** 都可以在 GitHub 上直接看到这个仓库
- 适合：开源项目、学习笔记、技术分享、博客源码
- 优点：别人可以 Star、Fork、提 Issue、提 PR，帮你改进
- 缺点：代码完全公开，不适合放敏感信息

### 3.2 Private（私密）仓库

- 只有**你明确授权的人**才能看到
- 适合：商业项目、未发布产品、内部工具、个人练习
- 免费版 GitHub 也支持私密仓库（数量有限制）
- 协作时必须邀请协作者（详见第四节）

### 3.3 如何切换公开/私密

> ⚠️ **重要提醒**：将公开仓库改为私密，是**不可逆**的"安全"操作（虽然技术上可以再切回公开，但别人已经 Fork 走的代码你控制不了）。反过来，把私密仓库改成公开是**可逆**的，但公开前请务必检查里面有没有敏感信息（如 API Key、密码）。

操作步骤：

1. 进入目标仓库页面
2. 点击上方的 **Settings**（设置）标签
3. 滚动到页面最下方的 **Danger Zone**（危险区域）
4. 找到 **Change repository visibility**（更改仓库可见性）
5. 点击 **Change visibility**
6. 选择目标状态：
   - **Make public** → 公开
   - **Make private** → 私密
7. 按提示输入仓库名确认
8. 点击 **I understand, change repository visibility** 完成

> 免费用户把公开仓库改为私密时，可能会消耗你的"私有仓库额度"，请提前了解 GitHub 的免费政策。

## 四、邀请他人作为协作者（Collaborator）

当你希望别人一起编辑你的私密仓库，或者共同维护一个公开仓库时，就需要邀请协作者。

> **注意**：协作者功能主要针对 **Private（私密）仓库** 使用。Public 仓库理论上任何人都能 Fork，但"Collaborator"是你主动授予某人对**主仓库**直接写入权限的方式。

### 4.1 邀请步骤

1. 进入目标仓库页面
2. 点击 **Settings** → 左侧菜单的 **Collaborators**（协作者）
   - 部分新版界面也可能叫 **Collaborators and teams**
3. 点击 **Add people**（添加成员）按钮
4. 在搜索框中输入对方的：
   - GitHub 用户名，或
   - 注册邮箱
5. 从下拉列表中选中目标用户
6. 点击 **Add <username> to this repository**
7. 邀请发起后，对方会收到一封**邮件通知**，同时 GitHub 站内消息也会提醒

### 4.2 对方如何接受邀请

被邀请的协作者需要：

1. 登录自己的 GitHub 账号
2. 打开邀请邮件，或访问 [https://github.com/notifications](https://github.com/notifications)
3. 在通知列表中点击 **View invitation**
4. 点击 **Accept invitation** 接受邀请

接受后，对方就可以：

- 直接 `git clone` 这个仓库
- `git push` 到主分支
- 创建分支、提 PR、Review 代码
- 处理 Issue 等

### 4.3 协作者权限说明

GitHub 仓库协作者默认拥有 **Write（写入）权限**，可以：

| 操作 | 是否允许 |
| --- | --- |
| 查看代码 | ✅ |
| 推送提交（Push） | ✅ |
| 创建分支、Tag | ✅ |
| 提交 PR、Review | ✅ |
| 处理 Issue | ✅ |
| 修改仓库设置 | ❌（只有 Owner 能） |
| 删除仓库 | ❌（只有 Owner 能） |

如果你需要更细粒度的权限控制（读、写、管理员），建议：

- **公开项目**：把对方升级为 **Maintainer**（在 Settings → Collaborators 中可设置）
- **私密项目 / 团队项目**：升级为 **GitHub 组织（Organization）**，并通过 Team 管理权限

### 4.4 移除协作者

如果某协作者不再参与项目，Owner 可以在 **Settings → Collaborators** 中找到对应用户，点击右侧的 **Remove** 按钮即可移除。移除后对方会立即失去写入权限（但已经 Fork 的私有仓库可能仍然保留，需要单独清理）。

## 五、常见问题 FAQ

**Q1：注册时收不到验证邮件怎么办？**
A：检查垃圾邮件箱；确认邮箱拼写无误；可以点击注册页的 **Resend verification email** 重发。

**Q2：私密仓库会被搜索引擎收录吗？**
A：不会。GitHub 对私密仓库有严格的访问控制，不会被 Google、Bing 等索引到。

**Q3：免费账号可以创建多少私密仓库？**
A：GitHub 政策不定期调整，目前（2024+）免费账号可以创建**无限**的公开仓库和有限数量的私密仓库（通常为 3 人以下协作规模可免费）。建议查阅官方最新政策。

**Q4：协作者一定要有 GitHub 账号吗？**
A：是的，所有协作者都必须先注册 GitHub 账号才能被邀请。

**Q5：把公开仓库改私密，原来的 Star 和 Fork 怎么办？**
A：Star 会自动失效，Fork 出来的副本在你切回公开前对原 Fork 作者不可见。

**Q6：能否只给某个人"只读"权限？**
A：免费版 GitHub 没有"只读协作者"角色。要实现只读，可以把对方加到团队并分配 **Read** 角色（需组织版），或者在私密仓库里把对方设为协作者但只给他**查看权限**（需要组织或付费方案支持）。
